# Постоянная память групп

Каждая подключённая группа хранит отдельную SQLite-базу:
`data/group_memory/<отрицательный chat_id>/memory.db`. Внутри записи и rolling
summary разделены по Telegram `user_id`. Топики одной группы используют общую
память участника; последние сообщения AGY по-прежнему разделены по топикам.
Личная `data/memory.db` владельца не читается и не изменяется этим механизмом.

## Что сохраняется

- Доставленные Telegram сообщения людей в подключённой группе, в том числе
  без префикса. Команды и анонимные отправители не записываются. Для доставки
  обычных сообщений нужен отключённый privacy mode либо права администратора.
- Собственный текст автора/подпись, ID события, дата и топик; процитированные
  чужие реплики не приписываются автору. Без текста сохраняется `[media]`:
  эта память не выполняет фоновое распознавание всех чужих медиа.
- Завершённые ответы Geminka в контексте этого участника. Повторная доставка
  Telegram-события не дублирует запись. Оригиналы сохраняются после сжатия.

Саммари строится отдельным фоновым SummaryWorker после пяти секунд простоя
участника и при накоплении минимум восьми записей либо 8000 символов.
Один проход берёт максимум 24 записи. Следующие обращения запускают следующие
проходы; незавершённая очередь проверяется также при запуске бота.
Между группами одновременно выполняется не больше одного фонового сжатия.
Новый запрос участника отменяет его текущую задачу сжатия, не уничтожая оригиналы.
Сжатие идёт в отдельном AGY-процессе с групповой песочницей, без приватной памяти
и MCP-ключей; инструкции требуют не запускать инструменты и не выдумывать факты.
Ошибка провайдера оставляет исходные записи для следующего прохода.

## Как вспоминает

Перед ответом выполняется SQLite FTS5 MATCH с ранжированием BM25 по текущей
реплике, строго в базе текущей группы и для текущего автора. Подтягиваются
саммари и до пяти подходящих записей. В живую AGY-сессию передаются только
обновлённое саммари и ещё не переданные находки (до 1000 ID на сессию).
Каждый найденный текст сокращается до 1000 символов; оригинал остаётся в базе.
Сброс/смена AGY-сессии не удаляет SQLite-память и получает актуальный контекст.
Саммари содержит сжатые сведения, а не отдельную автоматически достоверную
таблицу психологических фактов; ответы ассистента не считаются заявлениями автора.

Для углублённого поиска модель может использовать:

`collector_call(tool_name="group_memory_search", arguments={"user_id": 123, "query": "чай отпуск", "limit": 5})`

Пустой `query` возвращает саммари. Мост принудительно привязывает этот инструмент
к текущей подключённой группе; передать чужой `chat_id` нельзя. Можно вспомнить
другого участника той же группы по точному ID, но не его личные переписки.
Инструмент работает и без настроенного внешнего Telegram Collector MCP.
Внешний архив групп/каналов остаётся отдельным источником информации.

## Ограничения

- Память накапливается с момента включения функции: автоматического импорта
  старого архива MCP и пересборки всех прежних диалогов нет.
- `/debug` соответствующего пользователя отключает новые записи и сохранение
  его саммари. Уже записанные сведения остаются читаемыми.
- Файлы баз, WAL/SHM и саммари находятся под существующим Git ignore для `data/`.
  Они не монтируются в групповую песочницу: чтение выполняет доверенный мост.
- `/forget` в личке очищает личную память, а не групповые базы. Управление
  удалением групповой памяти отдельной командой пока не добавлено.
