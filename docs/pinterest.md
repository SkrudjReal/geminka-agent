# Pinterest: авторизация поиска

Анонимный API Pinterest может возвращать пустую выдачу даже по существующему
запросу. Это не означает, что картинок нет: проверяйте с авторизованной сессией.
Браузерный поиск без авторизации тоже может не показывать пины.

Экспортируйте cookies своей Pinterest-сессии в JSON-массив, совместимый с
`pinterest-dl.with_cookies_path`, и сохраните файл локально, например
`data/pinterest-cookies.json`. Не отправляйте содержимое cookies в чат или Git.
Ограничьте доступ к файлу (`chmod 600 data/pinterest-cookies.json`).

В `.env` укажите абсолютный путь:

```dotenv
PINTEREST_COOKIES_FILE=/absolute/path/to/data/pinterest-cookies.json
```

Перезапустите целевой экземпляр бота. Параметр применяется и к фотографиям
«покажи себя», и к подбору изображений для постов. Если поиск снова пустой,
проверьте срок действия cookies и сам запрос. Авторизация не гарантирует выдачу.

`data/` уже исключена из Git, кроме явно разрешённых дефолтных каталогов.
История отправленных картинок остаётся в `data/pinterest_self.db`; подключение
cookies не сбрасывает историю и не разрешает повторы.

Поиск проходит страницы через `iter_search`: до 200 результатов плюс запас
на уже использованные ссылки (максимум 1000 результатов за запрос).
Использованные URL картинки и пина исключаются до скачивания. Из оставшейся
выдачи случайно скачиваются до 80 изображений; до 40 подходящих входят в пул
выбора. В Telegram отправляется максимум 10 за запрос. Визуального поиска дубликатов нет.

## Проверка содержимого и видео

Для «покажи себя» доступны фото и MP4-видео (до 49 МиБ и 10 минут).
Из видео извлекаются три кадра: 20%, 50% и 80% длительности. Посты по-прежнему
подбирают только изображения, если скрипт не запущен с `--include-videos`.

После исключения использованных ссылок Gemini получает пиксели напрямую через
ACP: отдельное фото при запросе одного вложения, либо пронумерованные коллажи
до 10 кандидатов. Проверка оставляет только Коломбину — косплей с человеком
либо аниме; отдельная одежда, аксессуары и чужие персонажи исключаются.
Это проверка соответствия персонажу, не поиск визуальных дубликатов.
У проверяющего запроса нет MCP и истории личного диалога; процесс закрывается
после проверки. При ошибке или невалидном JSON непроверенное медиа не отправляется.

Тег `<tg-send-photos count="10" type="photo"/>` выбирает только фото;
`type="video"` — только видео; без `type` доступны оба вида. Смешанные вложения
отправляются альбомом, максимум 10. Это отдельный LLM-запрос перед отправкой,
поэтому время ответа увеличивается. Релевантность оценивается моделью и не гарантируется.
