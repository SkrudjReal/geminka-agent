# Инициативные ответы по пачкам

В настроенных `/chats` группах и `/topic` топиках наблюдатель сохраняет входящие
сообщения в `data/chat_observer.db` (SQLite WAL). Ключ — `chat_id + message_id`;
пачки разделены по группе и топику. Лички не читаются. `/debug` запрещает запись
сообщений этого пользователя. Файлы SQLite уже исключены существующим `.gitignore`.

После 100 новых сообщений один фоновый worker передаёт только эту пачку в отдельный
одноразовый AGY-вызов без инструментов. Обычная сессия пользователя не пополняется.
Модель возвращает `NO_REPLY` или короткий текст и ID сообщения из пачки. Ответ —
нативный reply в исходном топике. Адресованные боту сообщения учитываются как
контекст, но не выбираются целью: на них отвечает обычный обработчик.

Правила: `agent_skills/geminka/references/chat-observer.md`. Промпт перечитывается
перед каждой генерацией. Инициатива не обязана срабатывать на каждую пачку.

Пачка помечается обработанной до вызова модели: после сбоя, таймаута или неясного
результата отправки автоматического повтора нет. При перезапуске неполные пачки
сохраняются. Удаление группы из настроек запрещает дальнейшую обработку и отправку.
Архив автоматически не удаляется; следите за размером SQLite.

Сервис запускается вместе с ботом. Проверка без публикации в Telegram:
`uv run pytest -q tests/test_chat_observer.py`.
