# Групповой mod

- В личке бот отвечает только владельцу, независимо от legacy allowlist/allow-all.
- В `/chats` отвечают на префикс или реплай к самой Geminka; в `/topic` префикс
  не требуется. Доступны все обычные участники, но не боты и анонимные отправители.
- Обращение распознаётся отдельным словом в любой части текста, без учёта
  регистра и с поддержкой склонений: `сколько тебе лет клумба` тоже срабатывает.
  `суперклумба` и `геминка123` не срабатывают. Имя внутри фразы не удаляется.
- Подключение группы, модель и остальные настройки по-прежнему меняет владелец.
- LLM выбирает обычное сообщение или `<tg-reply/>`. В группе транспорт ждёт
  завершения текста, чтобы поздний тег реплая тоже сработал; личка стримится.
- Контекст разделён по пользователю/чату/топику, mood — по user_id.
- [Постоянная групповая SQLite-память](group-memory.md) хранит переписку и фоновое
  саммари по `(chat_id, user_id)`, автоматически ищет FTS5/BM25 перед ответом и
  доступна через read-only `group_memory_search`. Личная память в неё не входит.
- В начале живой AGY-сессии добавляются последние 100 доступных сообщений
  группы/темы, затем — только новые, без повторной отправки старой сотни.
  Учитываются сообщения без префикса и отправленные текстовые ответы бота.
  Текст каждой записи ограничен 700 символами с предупреждением модели.
  Курсор обновляется только после успешного AGY-ответа. Новый процесс/смена
  модели получают свежий стартовый контекст, не унаследованный курсор.
- По точному user_id автоматически собирается архивный контекст: до 100 реплик
  с 20 примерами по всему найденному периоду, частые слова/фразы на выборке
  до 5000 сообщений и до 8 явных reply-партнёров. Это факты архива, не
  психологический диагноз или доказательство дружбы. За деталями модель
  инструктируется обращаться к MCP самостоятельно и использовать находки
  естественно, не выдавая домыслы за цитаты.
- Сводка кэшируется на 10 минут отдельно для чата/темы/пользователя; в сессию
  передаётся только при первом использовании или обновлении. Ошибки кэшируются
  на 30 секунд. Запросы идут параллельно, каждый ограничен 3 секундами;
  недоступность архива не блокирует обычный ответ.
- Если новых сообщений больше 100, передаётся последняя сотня с признаком
  возможного пропуска. Внутреннее сжатие контекста самим AGY здесь не отслеживается:
  управление его окном остаётся за провайдером, а повторная загрузка выполняется
  при создании новой живой сессии.
- Локальный буфер живёт до перезапуска; MCP дополняет его архивом. Без архива
  нельзя восстановить пропущенные сообщения. Для получения обычных групповых
  сообщений отключите BotFather privacy mode либо выдайте боту права администратора.
  Отдельные темы не смешиваются; личная память владельца не подключается.

## Изоляция

Каждый chat_id использует отдельный AGY HOME/workspace с суффиксом `mod-<id>`
и `data/agy_groups/<id>/`. Bubblewrap создаёт отдельное дерево файловой системы:
код и публичные каталоги видны read-only, `.env`, личные SQLite-базы, `.git`,
Windows-диски, домашние документы и приватная история AGY не подключаются.
Вложения текущего чата подключаются read-only; их сохраняет основной бот.
Рабочая папка и служебные файлы собственного mod-профиля остаются writable.
`/sandbox off` владельца не снимает ограничения группового режима.

Групповой процесс не получает bot token и полный токен коллектора. Локальный
MCP-мост в основном процессе выдаёт отдельную capability для chat_id, проверяет
актуальную регистрацию группы и ограничивает инструменты/фильтры. Участники
подключённых чатов могут читать архив любых групп и каналов через MCP:
`list_chats` показывает доступные чаты, поиск принимает отрицательный `chat_id`,
аналитика — `scope.chat_id`. Без ID методы `search`, `semantic_search` и
`search_messages` ищут сразу по всем группам/каналам; мост принудительно передаёт
`public_only=true` для серверного исключения личек до ранжирования.
Аналитика без ID остаётся в текущей группе. Нужна обновлённая версия MCP коллектора.
Поисковые ответы содержат полные тексты сообщений с ID источников, без лишних
SQL-полей и дублирующих JSON-копий. Ограничения в 900 символов на сообщение и
16 тысяч символов на выдачу отсутствуют. `get_message` нужен только для
дополнительного контекста. Покрытие поиска (`truncated`, `warnings`) сохраняется.
`list_chats` возвращает компактную страницу названий/ID/username/типа без описаний
и дублирующих JSON-копий, с `next_after_chat_id` для продолжения. Обычная просьба
о названиях не должна запускать полный обход архива или статистику всех чатов.
Личные чаты с положительными ID запрещены; их строки и cross-chat цитаты
удаляются из результатов. Глобальные профили
`list_users`, `get_user_history` и `archive_status` не открываются.
Автоматический контекст последних сообщений остаётся локальным для группы/темы.
Личные memory-инструменты и произвольные Bot API-вызовы
недоступны. Исходящие файлы ограничены собственными вложениями отправителя
в этом чате и двумя встроенными портретами персонажа.

Это не изоляция сети: AGY нужны сеть и его авторизация у модельного провайдера,
а групповому MCP — localhost-мост. OAuth runtime AGY остаётся доступен самому
AGY. Не подключайте непроверенные плагины/дополнительные MCP в этот профиль.
Служебный `bin/agentapi` AGY может создавать внутри собственного mod-профиля;
общие установленные бинарники подключаются поштучно read-only, не writable.
Изоляция требует Linux/WSL с bubblewrap; legacy OMP в группах отклоняется.

Из архива можно узнать только то, что реально сохранено в выбранной группе/канале.
Партнёры по reply — наблюдённые связи сообщений, не доказательство дружбы.

Антифлуд, квоты запросов и отдельные лимиты памяти/CPU групповых процессов
пока не реализованы. Не открывайте бота большой недоверенной аудитории без
этих ограничений: участники могут расходовать общую квоту модельного провайдера.
